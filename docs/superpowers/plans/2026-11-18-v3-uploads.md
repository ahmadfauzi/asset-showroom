# v3 Uploads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People upload a .zip holding a texture, a model or an HDRI. It is shrunk once, kept in the browser, and can be used straight away: textures on any surface, models placed and moved in the room, HDRIs as the Garden's sky.

**Architecture:** Everything for uploads lives in `src/uploads/`. A small part loads at start: the IndexedDB store, the code that turns stored blobs into three.js objects, the Uploads tab and the upload button. The heavy part loads only when someone uploads: reading the zip, `FBXLoader`, `GLTFExporter`, and a Worker that decodes HDRIs. `main.ts` treats an upload id (`u-…`) like a texture slug wherever it looks up a texture. `RoomState` gains placed models and a sky, so the share link and undo cover them with no change to `history.ts`.

**Tech Stack:** Vite 8, TypeScript, three.js 0.183 (`FBXLoader`, `GLTFLoader`, `GLTFExporter`, `EXRLoader`, `HDRLoader`, `EXRExporter`, `PMREMGenerator`), `fflate` from `three/examples/jsm/libs/fflate.module.js`, IndexedDB, `OffscreenCanvas`, Web Workers, Playwright 1.61, sharp (fixtures only).

**Spec:** `docs/PRD.md`, section 16 (v3). Sections 6 to 15 still apply where 16 doesn't change them.

## Global Constraints

- three.js stays at 0.183.x. No UI framework. No new runtime or dev dependency. Unzip with three's bundled `fflate`.
- Upload code (`FBXLoader`, `EXRLoader`, `HDRLoader`, `GLTFExporter`, `EXRExporter`, `fflate`, the zip and processing modules) is only reached through `import()`. It adds nothing to first load. The JavaScript loaded at start may grow by no more than 30 KB (16.11, raised from 10 KB on 19 Nov 2026).
- First load for any one room stays under 15 MB. Uploads come from IndexedDB and don't count.
- Limits (16.3): zip 250 MB (`250 * 1024 ** 2` bytes), unzipped total 1 GB (`1024 ** 3`), 500,000 triangles, HDRI 8192 × 4096, 10 models per room.
- User-facing text is copied exactly from PRD 16. Every name from a zip or the hash is set with `textContent`, never as HTML.
- Upload ids look like `u-` plus 8 lowercase hex characters, from `crypto.getRandomValues`.
- `prefers-reduced-motion`: no spread animation and no tweens, as in v2.
- Every HUD control works with the keyboard, has a visible focus ring and has an accessible name. The existing test `every HUD button has an accessible name` must keep passing.
- Keys in PRD 6.10 keep working. Model keys (arrows, `Q`, `E`, Delete, Backspace) act only while a model is selected, and never while focus is in an `input` or `textarea`.

### Task 1: Detecting the kind and checking limits

**Files:**
- Create: `src/uploads/types.ts`, `src/uploads/detect.ts`
- Test: `tests/units.spec.ts`

**Interfaces:**
- Produces in `types.ts`:
  - `type Kind = 'texture' | 'model' | 'hdri'`
  - `type ZipEntry = { name: string; size: number }` (size is the unpacked size in bytes)
  - `class UploadError extends Error {}`. Its `message` is the exact text to show. This is the one runtime export in `types.ts`.
- Produces in `detect.ts`:
  - `MESSAGES` (the PRD 16.3 and 16.4 messages): `{ zipSize: 'This zip is over 250 MB.', unzipped: 'This zip unpacks to more than 1 GB.', triangles: 'This model has more than 500,000 triangles.', hdriSize: 'HDRIs up to 8K only.', quota: 'Your browser is out of space for uploads. Delete some in Uploads and try again.', memory: 'This file is too big for this device.', exportFirst: 'Export it as .glb or .fbx first.', nothing: 'This zip has no texture, model or HDRI we can read.', busy: 'Wait for the current upload to finish.', cap: 'This room has 10 models. Remove one first.' }`
  - `LIMITS = { zipBytes: 250 * 1024 ** 2, unzippedBytes: 1024 ** 3, triangles: 500_000, hdriWidth: 8192, hdriHeight: 4096, modelsPerRoom: 10 }`
  - `words(fileName: string): string[]`: the base name without folders, lower case, split on `_`, `-`, `.` and spaces, empty parts dropped.
  - `type MapRole = 'color' | 'normal' | 'ao' | 'roughness' | 'gloss' | 'metalness'`
  - `mapRole(fileName: string): MapRole | null`: a word matches a map word if it starts with it. Words, checked in this order: color `basecolor`, `albedo`, `diffuse`, `col`; normal `normal`, `nrm`, `nor`; ao `ambientocclusion`, `occlusion`, `ao`; gloss `gloss`; roughness `roughness`, `rough`; metalness `metallic`, `metalness`, `metal`. Only `.jpg`, `.jpeg`, `.png` and `.webp` files get a role.
  - `checkSizes(zipBytes: number, entries: ZipEntry[]): void`: throws `UploadError(MESSAGES.zipSize)` or `UploadError(MESSAGES.unzipped)`.
  - `detectKind(entries: ZipEntry[]): { kind: Kind; main: string }`: the rule in PRD 16.4. `main` is the mesh file, the colour map or the HDRI file. Ignores names with "preview" and folder entries. Throws `UploadError(MESSAGES.exportFirst)` or `UploadError(MESSAGES.nothing)`.

### Task 2: The upload store

**Files:**
- Create: `src/uploads/store.ts`
- Test: `tests/units.spec.ts`

**Interfaces:**
- Consumes: `Upload`, `UploadMeta`, `UploadFiles`, `UploadError` from `types.ts`, and `MESSAGES` from `detect.ts`.
- Produces:
  - `newId(): string`
  - `putUpload(upload: Upload): Promise<void>`: writes `meta` and `files` in one `readwrite` transaction over both stores. A `QuotaExceededError`, thrown or reported by the request or the transaction, becomes `UploadError(MESSAGES.quota)`.
  - `listUploads(): Promise<UploadMeta[]>`, newest first
  - `getFiles(id: string): Promise<UploadFiles | undefined>`
  - `setSize(id: string, sizeCm: [number, number]): Promise<void>`
  - `deleteUpload(id: string): Promise<void>`
- Database `asset-showroom`, version 1, object stores `meta` and `files`, both keyed by `id`. Use the plain IndexedDB API wrapped in promises. There is no library for this.

### Task 3: Reading the zip and processing a texture, with the fixture zips

**Files:**
- Create: `src/uploads/zip.ts`, `src/uploads/texture.ts`, `scripts/make-upload-fixtures.mjs`, `tests/fixtures/uploads/*.zip`
- Test: `tests/units.spec.ts`

**Interfaces:**
- Consumes: `mapRole`, `words` from `detect.ts`. `TextureFiles` from `types.ts`.
- Produces:
  - `listZip(data: Uint8Array): ZipEntry[]`: `fflate.unzipSync` with a `filter` that records `{ name, size: originalSize }` and returns `false`, so nothing is inflated.
  - `readZip(data: Uint8Array, names: string[]): Promise<Record<string, Uint8Array>>`: fflate's async `unzip` with a filter for `names`.
  - `processTexture(files: Record<string, Uint8Array>): Promise<{ files: TextureFiles; thumb: Blob }>`. `files` holds every image with a map role.
  - `encodeImage(canvas: OffscreenCanvas, quality = 0.9): Promise<Blob>`: WebP, or PNG when the blob comes back with a type other than `image/webp`. Task 7 reuses it. The colour map uses 0.9. Normal and ORM maps use quality 1, which Chromium writes as lossless WebP. Lossy WebP halves colour detail, which mixes the AO, roughness and metalness channels and blurs normals.
- Map sizes (PRD 16.5): colour up to 2048 px, normal up to 1024 px, ORM the colour map's size. Never scale up. Thumbnail 256 × 256 from the colour map.
- ORM: AO in red (white if missing), roughness in green (1 minus gloss if there is a gloss map and no roughness map, mid-grey 128 if neither), metalness in blue (black if missing). Normal map: flip green when the file name matches `/DX/` (case-sensitive), the same as `scripts/build-textures.mjs:106`.
- Fixture script: `node scripts/make-upload-fixtures.mjs` writes these into `tests/fixtures/uploads/`. Images are 64 × 64 PNGs made with sharp. Zips are written with `zipSync` from `three/examples/jsm/libs/fflate.module.js`.

    const z = await import('/src/uploads/zip.ts');

    const pixel = async (blob: Blob) => {

      const canvas = new OffscreenCanvas(bitmap.width, bitmap.height);

      ctx.drawImage(bitmap, 0, 0);

### Task 10: Processing an HDRI in a Worker

**Files:**
- Create: `src/uploads/hdri.worker.ts`, `src/uploads/hdri.ts`
- Modify: `src/uploads/process.ts`, `scripts/make-upload-fixtures.mjs`, `tests/fixtures/uploads/*`
- Test: `tests/units.spec.ts`

**Interfaces:**
- Consumes: `LIMITS`, `MESSAGES`, `SkySun`.
- Produces:
  - `processHdri(name: string, bytes: Uint8Array): Promise<{ files: { exr: Blob }; thumb: Blob; sun: SkySun }>` in `hdri.ts`. It starts `new Worker(new URL('./hdri.worker.ts', import.meta.url), { type: 'module' })`, transfers the bytes, and ends the Worker afterwards. A Worker `error` event, or a message `{ error: 'memory' }`, becomes `UploadError(MESSAGES.memory)`. `{ error: 'size' }` becomes `UploadError(MESSAGES.hdriSize)`.
  - Worker steps:
    1. Read the width and height from the header first (the EXR `dataWindow`, or the `.hdr` resolution line). Over 8192 × 4096: post `{ error: 'size' }`.
    2. Decode with `EXRLoader` or `HDRLoader` `parse`, with `setDataType(HalfFloatType)`. The 634 MB measured for the 8K example was with half float. Float would double the decoded image to about 537 MB.
    3. Box-filter it to 2048 × 1024, converting half floats to numbers block by block with `DataUtils.fromHalfFloat`. Never scale up: a smaller source keeps its size.
    4. Find the sun: average the scaled image in 32 × 32 blocks and take the block with the highest luminance (`0.2126 R + 0.7152 G + 0.0722 B`). Its direction uses three.js's equirect mapping: `u` and `v` are the block's centre in texture coordinates with `v = 0` at the bottom row; `angle = (u - 0.5) * 2π`, `elevation = (v - 0.5) * π`, `direction = (cos e · cos a, sin e, cos e · sin a)`. Colour: the block's average divided by its largest channel. If `elevation < 0`, `sun = null`.
    5. Write the scaled image with `EXRExporter` (`HalfFloatType`, ZIP compression) and a 256 × 128 thumbnail (Reinhard tone mapping, sRGB) with `OffscreenCanvas.convertToBlob`.
    6. Catch `RangeError` and post `{ error: 'memory' }`.
- Fixtures added to the script, both 512 × 256, black except a white 32 × 32 square centred at pixel (128, 64) from the top-left:
  - `hdri-exr.zip`: `Sky_HDR.exr`, written with three's `EXRExporter` in Node from a `DataTexture`.
  - `hdri-hdr.zip`: `Sky.hdr`, RGBE written by hand in the script.
  - `hdri-16k.zip`: `Big.hdr`, a valid header saying 16384 × 8192 followed by a few bytes of data.

  The square sits at u = 0.25, a quarter of the way down the image, so the expected sun is `elevation = +45°`, `angle = -90°`, and `direction ≈ (0, 0.707, -0.707)`. If three's rows run the other way, the test shows it and step 4 changes, not the expected value.
