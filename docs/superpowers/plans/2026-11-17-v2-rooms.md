# v2 Rooms and Visual Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single v1 flat with four switchable rooms (Living room, Bedroom, Bathroom, Garden), better furniture, snow, and a new look for the HUD and scene.

**Architecture:** Room data (surfaces and models per room) lives in one JSON file that the app and the Node build scripts both read. Each room is built by its own module into a `BuiltRoom`. `main.ts` keeps one `RoomSession` per room (textures, time, snow, undo history) and swaps the visible room. The share link moves to `v=2` with a `room` key.

**Tech Stack:** Vite 8, TypeScript, three.js 0.183 (GLTFLoader, KTX2Loader, meshopt decoder, `Sky`, `RoomEnvironment`), Playwright 1.61, sharp, KTX-Software `toktx`, `@gltf-transform/cli` 4.5 (dev only).

**Spec:** `docs/PRD.md`, section 15 (v2). Sections 6 to 13 still apply where 15 doesn't change them.

## Global Constraints

- three.js stays at 0.183.x. No UI framework. No new runtime dependency. `@gltf-transform/cli` is the only new dev dependency.
- First load for any one room stays under 15 MB (three.js, transcoder, that room's textures, models and thumbnails).
- 60 fps on a recent MacBook, 30 fps on a Windows laptop with integrated graphics, in every room. GTAO turns off first under 30 fps.
- `prefers-reduced-motion`: no tweens, no spread animation, instant room switch, snowflakes stay still.
- Every key in PRD 6.10 keeps working. Every HUD control works with the keyboard, has a visible focus ring and an accessible name.
- Text from the hash or manifest is set with `textContent`, never as HTML.
- Copy: plain, second person, short sentences. Neutral look, no Poliigon branding.
- Narrow screens (900 px and below): the room switcher stays visible and does not overlap the tray at 375 px.
- `toktx` (KTX-Software 4.4+) must be installed, or `TOKTX` set, for Tasks 1, 5 and 7. It is not on PATH on this machine today.
- Downloading Poly Haven files needs Ahmad's yes first. Ask with the file name, source URL and size, or ask him to download them.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

```ts
export type History<T> = { past: T[]; committed: T; future: T[] };
export function createHistory<T>(initial: T): History<T>;
// Pushes `next` unless key(next) === key(committed). Clears future. Returns true if it pushed.
export function commit<T>(history: History<T>, next: T, key: (state: T) => string): boolean;
```

```ts
export type BuiltRoom = {
  key: RoomKey;

```

- Produces in `src/daylight.ts`: `createDaylight(scene, reducedMotion, onUserChange)` with a new method `setRoom(room: BuiltRoom): void`, which replaces the lamps, the shadow area, and the glass and shade materials. `setTime`, `target` and `update` stay.

Behaviour in `main.ts`:
- A `RoomSession` per room, built the first time it is shown: `{ built, latest, current, history: History<RoomState>, time, snow }`.
- `applyTexture(session, slot, texture, dropPoint?)` captures the session. A texture that finishes after a switch still lands on its own room.
- `showRoom(key)` removes the old group, adds the new one, clears the selection, sets the camera to the room's `view`, calls `daylight.setRoom` and `setTime(session.time)`, calls `hud.setRoom`, and writes the hash. A room switch is not committed. A fade of 600 ms or less is fine. A later click wins over an earlier switch that is still running.
- Loading: the loader waits for `ktx2.init()`, the link's room defaults, that room's `models` and the thumbnails. Then it preloads that room's other textures, then the other rooms.
- Living room (about 7 × 5 m): the v1 living room and dining corner, the slat wall, a window and a floor lamp. Bedroom (about 6 × 5 m): the v1 bed, nightstands and lamps, rug, and the study desk and chair. A dresser goes here too. The desk chair's seat and back use `accents`.
